The tests still use ImageResizer.UnitTests.csproj and MSTest / Microsoft.Testing.Platform. A small native console helper supplies real Shell selections; it is not another test suite or general-purpose TestHost. No separate Integration layer was introduced.

04 · Semantic contract: selection becomes a pending task

Real modern-menu path

Explorer native handler
  → CreateNamedPipe (message mode)
  → Launch GUI with the full pipe path argument
  → Raw UTF-16 file paths + CRLF (no BOM)
  → GUI FromCommandLine / CliOptions.Parse
  → FromCliOptions receives → file list

Current Functional path

Native helper creates real IShellItemArray
  → Shared production pipe + selection writer
  → Message mode, BOM-free UTF-16 + CRLF
  → Managed FromCommandLine / FromCliOptions
  → Expected pending file set and destination
  → STOP: no user confirmation, no processing
Keep the coverage claim narrow: the same native pipe creation, connection and per-item writer functions are used by the modern command and test helper. The test does not invoke the actual COM command wrapper, register a menu, launch the GUI, exercise elevation variants, or click Resize.

Implemented Two cases select 2 and 128 real PNGs with spaces, Chinese text, an accent and a surrogate pair. Both add a corrupt PNG (retained until decoding) and an unsupported text file (filtered). The pending file set is exact and source bytes stay unchanged. The large case exceeds 16 KiB in aggregate; it does not require one overlong path.

This replaces the earlier single-path C# sender fixture, whose byte mode and BOM differed from production. An intentional native mutation omitting the first path made both new cases fail; the mutation was removed and final artifacts rebuilt.

The classic handler uses an anonymous pipe plus inherited stdin. The named-pipe test does not replace classic-entry checks; this pilot's agent E2E exercised modern resize and classic launch.

05 · The two retained agent E2E journeys

Local tests alone cannot establish real control actions, installed Shell registration, process handoff, UI bindings, and the final user outcome. Use representative inputs for these journeys rather than repeating parameter matrices already tested below E2E.

E1 · IR-E2E-RESIZE

Settings → Explorer → Resize → Output

Create and Save a Fit / Pixel preset through the actual Settings dialog; select a PNG and animated GIF in Explorer; invoke the modern menu; select the preset in the module; click Resize once.

  1. Preset connection: the name and dimensions created in Settings reach the module.
  2. Warning binding: the GIF animation warning is visibly displayed.
  3. Final result: two correctly named and sized outputs; original SHA256 values unchanged.

Observed: a 100 × 100 Fit preset produced a 100 × 50 PNG and 100 × 100 GIF. All three behavior observations passed.

E2 · IR-E2E-SHELL

Enablement → Real menu → Module launch

Disable and enable the module through Settings, observing the actual modern and classic menus without restarting Explorer or Runner.

  1. Disabled: the menu still works, but the Image Resizer command disappears.
  2. Enabled: the command and icon return; the classic entry opens a usable window, then Cancel closes it.

Observed: both menus were checked on Windows 11; both behavior observations passed. The Windows 10 branch was not run in this pilot.

C# UITests are outside this change scope. The old suite still exists, but its source presence or unexecuted cases are not evidence of passing this run. The reduction targets the verification skill's checklist.

06 · Verified evidence and limits of the coverage claim

Established: the current complete non-UI suite passed 159/159 with no skips. The native sender was extracted without changing business logic; the helper and production Shell DLL built successfully (MSIX packaging excluded). Earlier revised-inventory checks and all five retained agent E2E behavior observations passed; those installed-build results are historical, not a rerun of the refactored DLL.

Non-UI tests ran against a local source build. Agent E2E used installed PowerToys 0.102.2933.0 and winapp 0.7.1. These are distinct recorded artifact identities, not an assumption that the installation exactly matches the checkout.

Local paths and branches still insufficiently verified

  • Actual Shell command activation/GUI launch, classic inherited stdin, and permission, connection-race and disconnect matrices beyond the new pending-task cases.
  • The complete file-watcher / debounce / UI-dispatch update path; the settings Functional test explicitly calls Reload.
  • GUI error results, mid-run cancellation, and the native file picker. This E2E run primarily checked normal resize and menu enablement.
  • Full CLI process startup and exit codes; all codec / file-permission / disk-failure combinations; special AI / GPO branches.
  • Windows 10, ARM64, and other machine environments. The current 159/159 result cannot automatically be generalized to those platforms.
Overall E2E signoff: WITHHELD. All behavior observations passed. Original settings bytes / existence, enablement, test files and windows, original window placement, foreground, and pointer were restored. However, the initial snapshot could not fully certify restoration of the original Settings content page / scroll state. The baseline was not rewritten to manufacture a pass. This is a verification-tool preservation-boundary issue, not a resize-function failure.

Overall assessment: the original checklist's core processing rules and representative product connections have compositional coverage evidence, not “100% / 99% coverage” of the entire module. Scenario count fell by 83.3% and child assertions by 72.2%. This redistributes execution responsibilities; it is not code coverage.
